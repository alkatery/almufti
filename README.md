# almufti

اختبارات تفاعلية (الإملاء: `/`، الصرف الصغير: `/sarf/`) مع لوحة معلّم تقرأ النتائج من Supabase.

## تأمين قاعدة البيانات (إلزامي)

مفتاح `anon` في `assets/app.js` علنيّ بطبيعته، فلا يجوز أن يمنح القراءة. الحماية كلها في سياسات RLS:

1. **SQL Editor** ← نفّذ `supabase/security.sql` كاملًا.
2. أضف بريد كل معلّم (بأحرف صغيرة):
   ```sql
   insert into public.teachers (email) values ('teacher@example.com') on conflict do nothing;
   ```
3. **Authentication → Users → Add user**: أنشئ حساب المعلّم بالبريد نفسه وكلمة مرور قوية، مع تفعيل *Auto Confirm User*.
4. **Authentication → Sign In / Providers → Email**: عطّل *Allow new users to sign up*. (السياسات تمنع غير المسجّلين في `teachers` من القراءة على أي حال، لكن هذا يغلق الباب كليًّا.)

### ما الذي يضمنه
- الزائر يُدرج نتيجة فقط، ولا يقرأ ولا يعدّل ولا يحذف.
- القراءة لحسابات `teachers` فقط عبر تسجيل الدخول في لوحة المعلّم.
- كل سجل يُفحص خادميًّا: اتساق `correct/wrong/total/pct/passed/grade`، المادة، الأطوال وصيغة البريد؛ و`created_at` يضعه الخادم.
- حدّ طلبات: 15 محاولة لكل بريد في 10 دقائق، و120 إدراجًا في الدقيقة إجمالًا.

### حدّ معروف
التصحيح يجري في المتصفّح، فيستطيع شخص متمرّس إرسال نتيجة متّسقة غير مستحقّة. منع ذلك كليًّا يتطلّب نقل التصحيح إلى الخادم (Edge Function تحتفظ بالإجابات).

### تحليل «أصعب الأسئلة» (`supabase/002_wrong_items.sql`)
نفّذه بعد `security.sql`. يضيف العمود `wrong_items` (مواضع الأسئلة الخاطئة داخل الباب/القسم) وصلاحية إدراجه.
قبل تنفيذه تُحفظ النتائج كالمعتاد دون هذا العمود (تراجع تلقائي)، ويظهر التحليل للمحاولات الجديدة بعد تنفيذه فقط.

> لا تُعِد ترتيب الأسئلة داخل `data/*.js` ولا تحذف منها بعد جمع النتائج؛ التحليل يعتمد على موضع السؤال. الإضافة في آخر الباب آمنة.

### التحقق بعد التنفيذ
```bash
# يجب أن يعيد [] أو 401 — لا بيانات
curl -s "https://<project>.supabase.co/rest/v1/results?select=*&limit=1" -H "apikey: <anon-key>"
```
